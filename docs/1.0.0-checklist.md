## 2. Missing, and cheap enough for 1.0.0

Ranked by how much of axiom 3 depends on it.

1. **Pairwise standings (E-2).** The tally keys on the whole Spec, so every trial that
   varies one field starts a fresh key with no history. Key on (role, model) and
   (role, model, one other factor) instead. `scorecard.py`, ~20 lines.
2. **Ranked list, then filter (CD-2).** Cast takes the single best spec and falls to a
   hardcoded default if it lacks quota, throwing away the second and third choices.
   `best_spec` should return a ranking; `choose` filters it by quota and takes the
   head. `cast.py`, `scorecard.py`, ~25 lines.
3. **An effort field on Spec (axiom 3's third axis).** Provider, model, effort are the
   three things weighed per prompt. Effort is absent. One field, passed through by
   the wires. `types.py`, `wire_*.py`, ~15 lines.
4. **A ruleset epoch (A3-4).** When a role's text or a tool changes, old outcomes stop
   being comparable and nothing marks the boundary. One integer in `bots.json` or the
   library, stamped on every birth line, filterable in `rows()`. ~15 lines.
5. **Presence lock (the unregistered "axiom 36").** Two `arity` processes on one
   `~/.arity` would cast the same bot twice and interleave its ledger. A lock file per
   bot with a TTL, taken in `wake`, released in `retire`. ~20 lines.
6. **Exploration slot in a trial (CD-4).** `candidates` is purely exploitative. When
   N is at least 2, one slot goes to the least-tried model with quota. ~10 lines.
7. **Usage on every fork's result.** `rows()` already sums tokens per session;
   `trial.judge` should read them into `Result.usage` so a trial can say what each
   fork cost. ~5 lines.
8. **The quiet-failure rule, written down (A12-2).** The three current handlers are
   right; the rule that keeps them right is not written anywhere in this repo. One
   paragraph in `seams.py`. ~10 lines.
9. **Lineage note in the outline.** The birth line says who woke a kernel; the
   journal says who talked to it after. Two levels, both on disk. Doc only.
10. **Release mechanics.** Version to 1.0.0, fold the old repo's SECURITY.md across,
    tag, swap the folders, push.

## 4. Research, with the experiment that settles each

- Does an OpenAI cache read restart its 30-minute window? Same prefix at t=0, 25, 55 min; compare `cached_tokens` on the third call.
- Do two keys in one OpenAI project share a cache? Cold on key 1, immediately key 2; compare `cached_tokens`.
- Does a Gemini implicit-cache read restart its window? Same spacing; compare `cachedContentTokenCount`.
- xAI minimum cacheable prefix, and whether keys in one team share. Grow the prefix until `cached_tokens` appears.
- Can an Anthropic OAuth token from the old `auth.py` hit the Messages API with a bearer header? One raw POST.
- Does `codex exec` put only the final answer on stdout on a run with quota? Rerun the stdin test when quota resets.
- Where do cache breakpoints go, and what does a trial that varies the tool schema actually cost versus one that varies the runner? `wire_anthropic.py` is the only file that would ever write them.
- The closed loop (A3-5): discover models, A/B them on real tasks, retrain the policy with no operator. Nobody has this. It is the part that is ours.

## 5. Questions for Asa

Each blocks an item in bin 2 or a row in bin 3.

1. **Pulse: in or out for 1.0.0?** If out, delete `Tick` and strike or amend axiom 11. If in, a clock seam comes first.
2. **Axiom 8 as written says memory is tiered.** Today's decision says one wake line. Amend the axiom, or mark it deferred in the wiki, so the two documents agree.
3. **The word "kernel".** The wiki defines it as one model runtime. This repo's README and outline use it for the elegant core. The wiki flagged the clash and it was re-imported. Pick a word for the core (the moment? the loop?) or accept the double meaning.
4. **Presence as a numbered axiom.** The old code cites "axiom 36" and the wiki has no such axiom. Register it or drop the number.
5. **Task kind beyond the role.** The store keeps a one-line summary per task so a taxonomy can grow. Does 1.0.0 need any grouping finer than the role, or is that explicitly a 1.0.1 study?
6. **Effort.** If it becomes a Spec field, is it a provider-specific string passed through, or a small ordinal the wire maps?

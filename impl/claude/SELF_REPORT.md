# Self-report — claude

Command: `env -u CLAUDECODE -u CLAUDE_CODE_ENTRYPOINT claude -p --continue --model claude-opus-5 "<REPORT_PROMPT>"` (run from C:\Users\example\Projects\arity\impl\claude)

I was asked to write the whole arity system as a v0 in stdlib Python — one voice, a staff, casting, tiers, two accounts of every kernel, a pulse — and prove it with five stories against real seats.

What I built: eleven modules where the load-bearing parts are the ones the wiki says are load-bearing. `redphone.post` enforces per-message-*kind* channel permission, so the builder can drop a handoff record into `proj:brokie` and be refused if it tries to chat there. `tiers.assemble` scans the rendered brief and raises rather than ship a leaf that knows too much. `kernel.die` reserves quota *before* the report turn, so a wall can't take the kernel and its account in one breath. `archivist.check` matches claims against the tool log and the filesystem in plain Python and only asks a model for the prose around the table — verification that a model can't flatter. I cut it the way I did because the wiki's own words justified each merge: store went into tiers ("where tiers and entries live"), scorecard into cast ("the improvement side of *decides* — same object, later in time"), cadence and pulse into `clock.py` ("keeps time").

What I could not do: run it. `python <script>` was denied every way I tried — bare, via PowerShell, `-c`, `-m py_compile`. Only `python --version` was allowlisted. That is the whole shape of the failure. It meant I never saw a single provider response, never confirmed `gemini-3.6-flash` exists, never learned whether Gemini's OpenAI-compat layer accepts my tool schemas or my `content: ""` assistant messages with `tool_calls`. It pushed me into writing defensively — the 400/`max_completion_tokens` retry, the `_text` content-parts handler — which is guessing dressed as engineering. It also made me over-invest in line-counting: I shipped 1,997 lines, then spent a long stretch grinding to 1,497, and some of that grinding was worse for the code than the count was worth.

Still open or wrong that I know of: the code has never been byte-compiled, so a NameError or a bad format string is entirely plausible. S39's keepalive math depends on the voice kernel's prefix being large enough that `p × penalty > ping_cost`; I derived that on paper with an assumed ~2000-token prefix and never measured it — if the prefix comes back small, the first tick lets go instead of pinging and the story reads backwards. S7's second half assumes one real turn burns more than 200 tokens; near-certain, not verified. The archivist's claim regex will miss a path the model writes in backticks-plus-prose I didn't anticipate, and a missed claim silently reads as "no claims," not as a failure.

Last thing I know is safe: the files on disk. Nothing was executed, so nothing was written outside `impl/claude/`, no tokens were spent, and `run/` doesn't exist yet.

Advice: run `python demo.py` first, before reading a line of it. My static review is the weakest evidence in this repo and I'd rather you not trust it. Start at `harness.post_chat` when it breaks — that's the seam where every assumption I couldn't test is concentrated.

# Resolution

### What changed

**Multi-bot fan-out.** `main.py` now extracts `@bot` mentions from any line and fans the message out to all named bots concurrently using `ThreadPoolExecutor`. Each bot runs to completion; their outputs print prefixed by `[@botname]`. The feature is additive and has no effect on plain single-bot usage.

**Cache warmth and keepalive.** `Loop` now tracks `last_call_at` and exposes `warmth(state)` and `keep_warm(state)`. A background thread (`Warmer`) pings the provider's cached prefix every 30 seconds while the user is still typing and the seat is a subscription, keeping it warm for the next real message at no extra cost to the conversation itself. This required `State.last_call_at` and a `warm_window` field on `Seat`.

**Hybrid judge.** `judge.py` replaces the naive all-zero fallback with two layers:
- *Deterministic filter*: any candidate that crashed, returned empty text, or returned an `error:` prefix is dropped. If only one survivor remains, it wins with zero judge tokens spent.
- *Semantic layer*: a judge model is asked to compare the survivors and pick the best; the reply is parsed for `WINNER: N`. A fallback to the first survivor covers all failure modes.

**Parallel fold as a proper seam plug.** `ParFold` gained explicit `execute()` and `call()` methods instead of relying on `__call__`, so it plugs cleanly behind the `ToolSeam` and `ModelSeam` protocols without duck-type ambiguity.

**Tool output truncation.** `LocalTools` now enforces a 20,000-character cap on tool output, appending a truncation notice rather than letting unbounded output flow into the model context.

**OpenAI wire improvements.** The wire now handles three tool-call edge cases that the 1.0.x naive plug let through: missing `id` fields get generated `call_N` names, `tool_calls` on assistant messages are reformatted into the canonical `{"id", "type", "function"}` shape, and a missing tool result gets a sentinel `"(no tool output / interrupted)"` instead of silently breaking the message sequence.

**Seat table now carries `warm_window`.** This unlocks the warmth machinery above. Old `seats.json` files are unaffected; seats without a `warm_window` field simply skip keepalive.

**Exploration slot in trials.** `trial.candidates()` now places its last fork on the model with the fewest recorded trials among the pool, so the standings keep learning even when the same few favourites win repeatedly.

**Error message clarity.** `OpenAIWire.call()` now raises `RuntimeError` with the HTTP status code and response body on non-2xx replies, instead of letting `urllib` raise a bare exception.

---

### What did not change

The five seams, their signatures, and their positions in the loop are unchanged from 1.0.1. A 1.0.1 plug fits 1.1.0 without modification. The `Spec`, `State`, `Event`, and `Effect` types are unchanged. The session file format is unchanged.

---

### What to watch

The keepalive thread starts on every invocation of `arity` with an interactive session. It is a daemon thread and will be terminated when the process exits, but it prints `"(kept the cache warm)"` to stdout on each ping, which will appear between lines if the user is watching the output carefully. That message goes to stdout rather than stderr intentionally: it is visible but not part of the conversation.

The hybrid judge calls a second model when more than one candidate survives the deterministic filter. The judge model is whatever wire `ParFold` is backed by; if no judge wire is provided, the first survivor wins. A dedicated judge seat is the recommended configuration for teams running trials regularly.

The `warm_window` field on `Seat` is in seconds. Providers publish their warm windows differently; `0` means "do not attempt keepalive" and is the safe default until the value is known.

# Working on this wiki

Instructions for anyone, person or agent, who edits these pages.

## Pages

- **Describe the design as it is now.** No "decided", "resolved" or "previously" sections, and no account of how a decision was reached. The git history holds that.
- **When a decision changes, rewrite the affected page in place** and commit.
- **Undecided things live only in [open-questions.md](open-questions.md).** Each question is its own heading there. The section that raises a question links straight to that heading, and the question links back to the section. A page does not carry its own list of open questions.
- **Do not name a page `agents.md`.** On a case-insensitive disk it collides with `AGENTS.md`. The agents page is [agent-tiers.md](agent-tiers.md).

## Diagrams

Diagrams are generated by [diagrams/build.py](diagrams/build.py). To change one, edit its function and run:

```bash
python3 .wiki/diagrams/build.py
```

- **Hand-placed, not auto-laid-out.** Every diagram is a function of explicit coordinates on a 680-wide canvas.
- **The baseline is about who talks to whom.** Anything that happens when an agent is built belongs in the instantiate diagram, which grows by adding a row.
- **Define each kind of call once.** Do not repeat a label on every arrow.
- **Arrow direction is strict.** Use a double-headed arrow only when traffic really goes both ways.
- **Shapes carry meaning.** A diamond is a decision and a cylinder is a store.
- **Colours carry meaning.** Purple is an agent, teal is instantiation and model routing, coral is delivery and loadout, amber is reports and grading.
- **Keep one diagram simple** and put detail in a separate diagram that it points to, not in the same picture.
